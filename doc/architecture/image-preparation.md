# Original and Lanczos image preparation (M26)

M26 adds an inactive, synchronous, worker-compatible single-image service. No
normal application caller adopts it. It does not change acquisition, source
storage, rendering, export, settings, serialization, page geometry, masks, marks,
printing or cutting. There is no neural provider, recovered-detail claim,
scheduler, generic plugin registry or M27 implementation.

## API, validation and returned dimensions

```python
def prepare_image(snapshot, plan, *, mode: Literal["original", "lanczos"], cache: DerivativeCache) -> PreparedImage: ...
```

Mode and cache are required keyword arguments; the signature has no defaults.
Cache must be an explicit DerivativeCache. Construction is inert and Original
does not use it. None semantics remain deferred.

The frozen PreparedImage contains source_identity, canonical_dimensions,
encoded_bytes (excluded from repr/payload comparison), image_format,
actual_dimensions, target_ppi, target_dimensions, outcome, optional derivative_key,
reason and detail. All dimensions are immutable tuples and no model, document,
snapshot, decoded image, QPixmap or caller-owned collection is retained.

Actual Original/fallback dimensions come from the M24 inspected native dimensions,
not the requested target. Selected target dimensions are informational on those
paths. Returned processed PNGs have actual dimensions equal to the exact target.

M25's source/plan checks are extracted as validate_source_plan in
image_derivative.py. The request builder reuses it, preserving source SHA checks,
strict metadata/target types and plan consistency. Original and unavailable
provider paths call the same validator without a fake recipe or bypass flag.
Available processing uses request construction's validation; no unnecessary
second source hash is added on that path. Invalid mode/cache/snapshot/plan raises
TypeError/ValueError. A forged digest or inconsistent plan is never successful
Original fallback. Source bytes are not reopened during validation.

The M25 golden descriptor remains 805 bytes with key
`e817a0b7d4c3225d533726714604db6a1af679f57301302c64028be48746d089`.

## Outcomes and cache sequence

| Outcome | Bytes returned | Derivative key |
|---|---|---|
| original | Exact captured source bytes, native format/dimensions | none |
| cache_hit | M25-validated cached PNG | current request key |
| generated_cached | Newly produced, validated and committed PNG | current request key |
| generated_uncached | Validated PNG retained after write_failed | current request key |
| fallback_original | Exact captured source bytes after an expected optional failure | none |

Original performs no optional runtime discovery/import, source decode, resize,
re-encode, orientation, color conversion, mask or cache access.

Lanczos resolves the current optional runtime once, builds its real frozen recipe
and independently expected M25 request, then looks up that request. A hit skips
the producer entirely: no source decode, resize or encoding. M25 still validates
the cached PNG. Any CacheMiss, including corruption or lookup I/O failure, permits
fresh production. M25 owns PNG validation and manifest-last publication.

Store write_failed means PNG validation already succeeded, so the service returns
generated_uncached rather than discarding usable data. Store invalid_output means
the generated bytes are rejected; they are never returned as a processed image.
The coordinator performs no cleanup, repair, retry or failure caching.

Stable reasons are provider_unavailable, unsupported_source,
source_decode_failed, processing_failed and invalid_generated_png for fallback;
generated_uncached uses cache_write_failed. Details distinguish specific format,
profile, decode and encoding failures. Narrow processing failures are handled;
request validation and unrelated programming errors remain visible. There is no
service-wide except Exception.

If the current optional runtime cannot be imported or its PNG/zlib capability
cannot be resolved, source/plan is validated and Original fallback is returned.
This first coordinator does not search entries for unavailable historical
runtimes or invent older versions from manifests.

## Optional runtime and declared recipe

The optional extra is `image-processing = ["Pillow>=13.0,<14"]`. Existing core
dependencies and the Windows icon-packaging entry are unchanged. For development
in a separate environment, install the project with its image-processing extra,
or install the optional dependency explicitly; isolated validation pinned
`python -m pip install Pillow==13.0.0`. No package is installed/downloaded by
application code. Importing either preparation module and using Original works
without Pillow; it is imported only inside discovery.

One PillowRuntime binds the actual Image module and Pillow, processing Qt,
PySide6 and Pillow zlib codec versions used by both recipe and execution. The
recipe uses pipeline m26-image-preparation-v1, provider pillow-lanczos with the
actual version, operation whole-source-exact-canonical-target-v1 and model=null.
Source identity, source-inspection provenance, canonical geometry and exact
targets still enter through M25's descriptor; processing Qt is separately declared.

Versioned policies explicitly identify first-frame Qt/straight-RGBA8888 decode,
no automatic transform, Qt-exposed RGB ICC or untagged/no conversion,
straight-input/Pillow-associated-alpha resizing, no mask, full-image Lanczos,
and RGBA8 PNG level-4 encoding with no unrelated metadata. Parameters declare:

- Actual Qt, PySide6 and Pillow zlib codec versions.
- Frame 0, auto_transform=False, scaled_decode=False, normalization and the exact
  supported Qt format list.
- No color conversion/sRGB assumption, Qt-decoded sample space, RGB ICC
  preservation, untagged preservation, and unsupported non-RGB/invalid ICC cases.
- Preserved alpha and Pillow RGBA associated-alpha resampling.
- LANCZOS, reducing_gap=None, no crop/padding, whole image, skip interpolation at
  equal size, and no mask.
- PNG, RGBA, compress_level=4, optimize=False, metadata limited to the preserved
  RGB ICC profile, no DPI or EXIF.

Runtime versions are discovered, not hardcoded. The optional Pillow distribution
notice in ThirdPartyLicenses.md is sourced from the installed 13.0.0 MIT-CMU
license and attribution. No installer/release packaging was performed.

## Exact processing policy

On a miss, QImageReader reads snapshot.encoded_bytes through QBuffer with format
autodetection and autoTransform=False. It reads only frame 0, with no scaled
decode, and requires successful decoding and native dimensions/format matching
the snapshot. It never asks Pillow to decode/reopen the original or accesses a
source path, application model or QPixmap. Qt allocation limits are unchanged.

Accepted Qt formats: RGB32, ARGB32, ARGB32_Premultiplied, RGB888, RGBX8888,
RGBA8888, RGBA8888_Premultiplied, Indexed8, Grayscale8, Mono and MonoLSB. Other
formats, including higher-depth, floating-point and CMYK, are unsupported rather
than silently quantized. Supported samples are converted to straight
Format_RGBA8888 and copied into Pillow RGBA using Qt's actual bytesPerLine stride.

No color conversion or gamma linearization is introduced. Resampling occurs in
the Qt-decoded sample space. A valid RGB QColorSpace must expose encodable ICC
bytes, which are passed unchanged to PNG encoding. A valid non-RGB model is
unsupported. An invalid space with exposed ICC bytes is unsupported; an invalid
space without profile bytes remains untagged. A valid RGB space without profile
bytes is a processing failure. Gray/CMYK profiles are never attached to RGBA.
These are policies for the profile exposed by Qt, not a promise to preserve or
validate every original metadata item. APIs used are available at Qt 6.8 minimum.

Pillow's RGBA resize uses associated alpha; hidden straight RGB channels are not
filtered independently. Smaller sources enlarge, larger sources downsample,
mixed-axis sources map both axes, and equal-size sources skip interpolation but
still undergo declared normalization/encoding. plan.sufficient does not cancel
an explicit Lanczos choice. There is no thumbnail/crop/padding, artwork extraction,
sharpening, contrast operation or corner mask.

Encoding returns immutable RGBA8 PNG bytes using compress_level=4,
optimize=False and only the applicable RGB ICC profile. Source EXIF orientation,
text, timestamps, DPI and unrelated metadata are not copied. No PNG DPI is added;
physical placement remains canonical. Temporary Qt/Pillow images are released.

| Type | Canonical | 600 target | 900 target | 1200 target |
|---|---|---|---|---|
| Regular | 745 × 1040 | 1490 × 2080 | 2235 × 3120 | 2980 × 4160 |
| Oversized | 1040 × 1490 | 2080 × 2980 | 3120 × 4470 | 4160 × 5960 |

1200 remains an optional maximum. No nominal 63 × 88 mm recalculation is used.
M22's research EXIF transpose and sRGB conversion are deliberately not imported
into this policy. Custom source bytes can be processed, but adopting this raster
for CustomCard rendering still requires a later decision about its existing
forced-corner setting. CheckCard composition remains deferred.

## Focused validation and observed visuals

Separate runtime: Python 3.13.14, Qt/PySide6 Essentials/shiboken 6.11.2,
Pillow 13.0.0, Pillow zlib codec 1.3.1.zlib-ng, pytest 9.1.1,
pytest-qt 4.5.0, pytest-timeout 2.4.0. Pip check passed. Prior runtimes were not
modified. The established private wrapper redirects writable locations before
application imports, blocks real stores/network, restricts SQLite, verifies the
M26 package path, uses offscreen Qt and applies A4 only within the test process.

From the M26 worktree, `$Python` denotes the isolated runtime interpreter and
`$Review` its private review directory:

```powershell
$env:PYTHONPATH = $null
$env:M26_RUN_LABEL = 'preparation-tests-final'
& $Python -B "$Review\run_isolated.py" pytest `
  tests/test_image_preparation.py tests/test_image_processing_pillow.py `
  tests/test_image_derivative.py -q --timeout=30 --tb=short `
  --basetemp "$Review\pytest-preparation-final"
```

**119 passed in 5.53 s.** Extraction alone passed 68 identity checks. Coverage
includes the fixed M25 key, Original/no optional import or cache access, a fresh
process with Pillow blocked, unavailable/broken codec/import handling, invalid
input rejection on every path, generation then producer-free reuse, identity
invalidation, all four real targets, equal/sufficient/downsample/mixed-axis
behavior, cache miss/failure outcomes, rejected output, orientation/DPI policy,
all supported format normalization, actual padded row stride, transparent edges,
RGB ICC/untagged/Gray/invalid profiles, high-depth rejection, deterministic
uncached bytes, worker operation and no source path reopening/QPixmap creation.
Gray-profile and high-depth fallbacks return exact original bytes.

Private review artifacts contain five synthetic samples and seven full-resolution
PNG derivatives, including regular and oversized 600/1200 examples. Each first
result is generated_cached; all seven repeated requests are cache_hit with
identical bytes while producer invocation is blocked. Separate records demonstrate
unsupported-depth exact-original fallback and generated_uncached after injected
persistence denial. Recipes, descriptors, dimensions and output hashes are retained.

Agent visual inspection of the labelled comparison sheet found the asymmetric
red/green top and blue/orange lower markers unrotated, full-face mapping without
cropping, preserved transparent regions over a checkerboard, grayscale remaining
gray, and indexed samples normalized with smoothed transitions. Conventional
filtering softens and can ring at high-contrast boundaries; it does not recover
detail. RGB profile preservation is established by byte checks, not a visual
color-fidelity qualification. Preview checkerboards do not flatten the retained
full-resolution PNGs. No typography, recovered artwork, neural enhancement,
native interactive or physical print-quality claim is made.

The unchanged cache fault/interleaving matrix, full application, scene, source,
benchmark, network-loader, print and hardware suites were not rerun. No normal
app launch, catalog update, inference or printer/cutter job occurred. Future
adoption, scheduling, target UI, persistence, masking/composition, retention and
rendering/export integration remain outside this milestone.
